# Responsive UI audit

The current application renders through a single root route and switches dashboard workspaces internally. A direct `/calendar` URL is not a valid route and correctly falls back to the existing 404 page; visual checks should therefore exercise the root page and its in-app tabs rather than assuming nested routes.

The root preview currently shows the existing workspace-load error when the preview session is not authenticated or the database-backed snapshot is unavailable. This is a runtime state, not a frontend layout failure, and the page should remain readable, centered, and actionable in that state.

The responsive polish pass will preserve the current dashboard composition while adding global overflow protection, safe-area-aware spacing, minimum touch targets, stable typography, readable contrast tokens, input-size normalization, and mobile-specific stacking rules. The desktop composition should remain unchanged except for improved surface contrast and focus/press feedback.
The preview now renders the root dashboard and the Relationships workspace at 390px without page-level horizontal scrolling. The mobile dock is visible, the topbar actions remain inside the viewport, the main cards stack cleanly, and form controls are touch-sized. The root dashboard has a healthy vertical rhythm and readable dark-on-light contrast. One long Today task label is visibly truncated, so the final polish will allow important task copy to wrap to two lines while keeping rows bounded. Other tab captures taken concurrently can remain in a loading state during the initial database-backed request; visual validation should also include isolated tab captures after hydration.
The isolated mobile calendar capture exposed one regression in the generic mobile grid rule: the month view’s seven-column calendar was forced into a single column, producing a very tall vertical list. The fix is to scope the month view with a dedicated calendar class and preserve a locally scrollable seven-column grid; this keeps the page itself within the viewport while maintaining calendar usability. The same capture confirmed that short action labels now remain intact and the mobile voice dock does not create page-level horizontal overflow.
